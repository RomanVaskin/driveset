# OLNOO_ARCHITECTURE.md — DriveSet

Архитектурные решения. Обновлять при изменении системных фактов.

## Обзор

Статический сайт на Next.js App Router: главная, внутренняя `/plan` и
индексируемая посадочная `/okleyka-avto`. Server Components по умолчанию;
клиентские — только там, где нужна интерактивность (навигация, формы, runtime
media и квиз). Backend нет — по замыслу текущего этапа.

## Ключевые решения

1. **Контент отделён от разметки.** Всё в `lib/site-config.ts`
   (типизировано). Компоненты только рендерят. Это готовит почву под
   будущие per-service страницы, калькулятор и квиз без переписывания.
2. **Дизайн-токены в `globals.css`** (Tailwind v4 `@theme inline`). Тёмная
   графитовая тема, акцент — шампань/платина (`--primary`). Менять палитру
   только здесь.
3. **Секции — независимые компоненты** в `components/site/`. Добавление/
   перестановка секции = правка `app/page.tsx`.
4. **Яндекс Карта** — официальный `map-widget/v1` через `<iframe>`.
   Интерактивная, адаптивная, без API-ключа. Запрос адреса формируется в
   `site-config.ts` (`yandexMapSrc`).
5. **Форма заявки** — frontend-only, локальный success-state. Точка
   расширения помечена комментарием в `lead-form.tsx`.

6. **Внутренняя страница `/plan`.** Отдельный маршрут `app/plan/page.tsx` со
   своими `components/plan/*` и контентом в `lib/plan-config.ts` (тот же принцип
   «контент отдельно от разметки»). Свой хедер/футер, потому что лендинговый
   хедер использует якоря главной. Закрыта через `metadata.robots`
   (`noindex, nofollow`); canonical переопределён на `/plan` (иначе наследуется
   от layout и указывает на главную). Sitemap в проекте нет, поэтому исключать
   нечего; `Disallow` в robots.txt намеренно не добавляем — он мешает краулеру
   увидеть `noindex`. Страница описывает будущие функции, но не реализует их.

7. **Hero-видео.** Фон hero — обычный `<video autoPlay muted loop playsInline>`
   (без JS, hero остаётся server-компонентом) с внешним URL
   `https://driveset.ru/media/hero-optimized.mp4`; MP4 в репозиторий не кладём. Под видео
   лежит `next/image` с `hero-detailing.png` (он же `poster`): виден, пока видео
   грузится, если autoplay заблокирован или файл недоступен. Видео показывается
   только на `md+` и без `prefers-reduced-motion: reduce` (CSS
   `hidden md:motion-safe:block`); на mobile (< md) и при reduced-motion остаётся
   статичное фото. `object-contain` на mobile пробовали и отвергли: 16:9-ролик в
   высоком портретном hero превращается в узкую полосу. Читаемость текста держит тёмный оверлей в `hero.tsx`;
   при смене ролика проверять контраст заново.

8. **Portfolio media вне Git.** Оригиналы хранятся вне проекта в
   `/opt/olnoo/media/driveset/portfolio/` и никогда не изменяются pipeline.
   `scripts/process-portfolio-media.mjs` рекурсивно обрабатывает только три
   разрешённые категории и атомарно пишет производные в соседний
   `portfolio-web/`: для фото — WebP 640/1600 через `cwebp`, для видео — web-compatible
   H.264/AAC MP4 (`yuv420p`, faststart) и WebP poster. Стабильное имя включает
   hash относительного пути, поэтому одинаковые исходные filename не
   конфликтуют. `.media-state.json` (версия pipeline + size/mtime источника) и
   проверка реальных codec/размеров/MP4-атомов обеспечивают идемпотентность.
   Ошибка одного файла исключает только его и не прерывает общий проход;
   `manifest.json` содержит все остальные успешные элементы.

9. **Галерея из runtime manifest.** Серверный `gallery.tsx` сохраняет секцию и
   передаёт настройки небольшому client-компоненту. Тот загружает same-origin
   `/media/portfolio-web/manifest.json` с `cache: no-store`, валидирует категории,
   типы и префиксы путей, затем показывает фильтры, сгруппированные по услугам
   материалы в режиме «Все», превью и фото/video viewer.
   Большое фото или MP4 загружается только при открытии. При недоступном, пустом
   или некорректном manifest остаются четыре локальных fallback-изображения из
   `site-config.ts`; media-обновления не требуют новой сборки сайта.

10. **Контент главной.** Три услуги всегда идут в порядке: оклейка, полировка,
    химчистка. Оклейка визуально приоритетна и ведёт на зарезервированный URL
    `/okleyka-avto`, но сам маршрут в этапе 1 не создаётся. Подтверждённые телефон,
    Telegram, WhatsApp, наличие MAX, часы работы и trust-метрики живут только в
    `site-config.ts`; неподтверждённую ссылку MAX не выдумываем.

11. **Посадочная оклейки.** `/okleyka-avto` — отдельная статически
    пререндеренная страница со своим контентом в `wrapping-config.ts`, route
    metadata, OG image и JSON-LD. Основная разметка остаётся серверной; клиентские
    границы ограничены header, квизом, контактными действиями и runtime media.
    Главная не зависит от компонентов посадочной.

12. **Квиз без ложной отправки.** Пять вопросных шагов выполняются локально.
    Цена определяется только подтверждённой таблицей пакетов/элементов и
    показывается до подарка и контакта. Для `full-ppf` обычная цена 210 000 ₽,
    скидка 20 000 ₽ и акционная цена 190 000 ₽; матовый PPF и цветная оклейка
    скидку не наследуют. После выбора одного подарка пользователь переходит к
    прямым каналам связи. `lead_submit` не вызывается, пока отсутствует реальный
    `POST /api/lead` и подтверждённый успешный ответ.

13. **Wrapping media.** Посадочная повторно использует
    `parsePortfolioManifest`, но после валидации оставляет только video с
    `category=wrapping`. Hero и галерея используют WebP posters; MP4 отсутствует
    в DOM до открытия modal viewer и получает `preload="none"`. Запрос manifest
    разделяется между hero и галереей в рамках клиентской сессии. При ошибке не
    подставляются сгенерированные или чужие категории.

14. **Атрибуция и события.** `campaign-attribution.ts` фиксирует первый набор
    `utm_source`, `utm_campaign`, `utm_content`, `utm_term`, `yclid` в
    `sessionStorage`. `marketing-events.ts` задаёт события квиза и кликов и
    вызывает `window.ym` только при наличии валидного
    `NEXT_PUBLIC_YANDEX_METRIKA_ID` и уже загруженной Метрики. Сам счётчик и ID
    на текущем этапе не добавляются; внешней отправки без ID нет.

## Деплой

Автодеплой по push в `main`: `.github/workflows/deploy.yml` подключается по SSH
к production-серверу (KZ, secrets `SERVER_HOST`/`SERVER_USER`/`SERVER_SSH_KEY`),
обновляет код (`git reset --hard origin/main`), пересобирает (`pnpm install
--frozen-lockfile` + `pnpm build`) и перезапускает `driveset.service`, затем
проверяет `systemctl is-active` и `curl http://127.0.0.1:3230`. Актуальные
production-факты (сервер, путь, порт) — в `OLNOO_PROJECT_MAP.md`, не здесь.

## SEO groundwork

- Один `<h1>` (Hero). Иерархия `<h2>/<h3>` по секциям.
- `metadata` + Open Graph в `layout.tsx`; canonical на `driveset.ru`.
- JSON-LD `AutoDetailing` в `app/page.tsx`.
- Все изображения с осмысленным `alt`, `lang="ru"`.

## Точки расширения (этап 2+)

| Задача | Куда встраивать |
| --- | --- |
| Backend формы / Telegram-уведомления | `lead-form.tsx` (`handleSubmit`) → Route Handler `app/api/lead`. |
| Следующие страницы услуг | Отдельные App Router routes с изолированным конфигом по образцу `/okleyka-avto`. |
| Другие калькуляторы / квизы | Изолированные client-компоненты и чистая расчётная функция по образцу `wrapping-quiz.ts`. |
| CRM lead submit | `POST app/api/lead/route.ts`: server-side validation, rate limit/idempotency, secrets только на сервере, принудительный `project=driveset`; событие `lead_submit` только после 2xx. |
| Яндекс Метрика | Подключить подтверждённый счётчик и `NEXT_PUBLIC_YANDEX_METRIKA_ID`; текущий event adapter менять не требуется. |
| Согласие на ПД | Добавить подтверждённый текст и URL политики у будущей формы до включения `POST /api/lead`. |
| Изменение подтверждённых контактов | Обновить значения и ссылки в `site-config.ts`. |

## Ограничения / инварианты

- `next.config.mjs` содержит `typescript.ignoreBuildErrors: true` — `pnpm build`
  ошибки типов **не ловит**. Перед коммитом запускай `npx tsc --noEmit`.
- Рабочая директория на production-сервере совпадает с путём `driveset.service`:
  `pnpm build` в ней перезаписывает `.next` живого сайта. Проверочные сборки —
  в копии проекта вне этой директории.
- Не добавлять backend, оплату, CRM, личный кабинет на этапе 1.
- Держать 3–5 цветов и ≤2 шрифта.
- Не выдумывать контактные данные или идентификаторы, которых нет в подтверждённом наборе.
- Mobile-first; без горизонтального скролла; карта не ломает layout.
- Не добавлять portfolio-оригиналы и тяжёлые производные в Git; pipeline не
  должен удалять или перезаписывать исходники и не устанавливает system packages.
